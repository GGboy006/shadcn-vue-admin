## 一、模块概述

居委会模块是居民 Web 端的**居委会管理员后台**,与商户后台虽共用"商户后台用户类型"(userType ∈ {4,5,6}),但业务内容完全不同 —— 商户管商品/订单,居委会管公告/活动/资讯/服务等。两者菜单、页面、接口前缀(`/neighborhood` vs `/merchant-business`)完全独立,可视为两个系统。

本模块对接后端 `BusinessOrgController`(`/neighborhood`)与 `BusinessStationMasterController`(`/station`)。

## 二、架构设计

### 2.1 技术栈

- Vue 3 + TypeScript + `<script setup>`
- shadcn-vue(new-york 风格,基于 reka-ui)
- Tailwind v4(配置即 CSS)
- TanStack Vue Query(服务端状态)
- TanStack Vue Table(列表)
- vee-validate + zod(表单校验)
- Tiptap v3(富文本,headless)
- 文件系统路由(unplugin-vue-router)

### 2.2 类型基座

公共类型集中在 `src/services/types/response.type.ts`,对齐后端 `BaseResponse` / `PageResult` / `PageParam`:

```ts
interface IResponse<T> { code: number; msg: string; level?: string | null; data: T }
interface IPageParam { pageNum: number; pageSize: number; searchCount?: boolean }
interface IPageResult<T> { pageNum; pageSize; total; pages; list: T[]; emptyFlag: boolean }
```

开发初期收敛了 6 份重复的 `IPageResult` 定义,并修正 `IResponse` 字段名(`message` → `msg`,对齐运行时 `use-fetch.ts` 的判错逻辑)。

## 三、菜单与路由结构

### 3.1 菜单(居委会管理员登录后)

定义在 `src/composables/use-sidebar.ts` 的 `neighborhoodNavItems`,按 `userType===6` 分流到居委会专属菜单组:

```text
居委会后台
├─ 首页                    /neighborhood/home          (占位空页面,接口后补)
├─ 公告管理                /neighborhood/notice       (3.1)
├─ 活动管理 ▾
│  ├─ 活动分类             /neighborhood/activity-cate (3.2)
│  └─ 活动列表             /neighborhood/activity      (3.3)
├─ 广告管理                /neighborhood/banner       (3.4)
├─ 资讯动态                /neighborhood/dynamic      (3.5)
├─ 服务管理 ▾
│  ├─ 栏目管理             /neighborhood/unified      (3.6)
│  └─ 专题管理             /neighborhood/special      (3.7)
├─ 居委会信息              /neighborhood/org-info     (2.1/2.2)
├─ 服务热线                /neighborhood/service-guide (3.9)
├─ 在线留言                /neighborhood/leave-message (3.10)
└─ 居委会服务              /neighborhood/service      (3.11)
其他
└─ 设置
```

> **专题文章(3.8)不在菜单**:它是"专题管理"列表点击名称进入的详情子页,路由 `/neighborhood/special/[specialCode]/article`。

### 3.2 路由

文件系统路由,页面放 `src/pages/neighborhood/<资源>/` 自动生成。动态参数路由用 `[param].vue` 命名,如 `special/[specialCode]/article.vue`。

权限:每个页面 `<route lang="yaml">` 加 `meta.roles: [6]`,仅居委会管理员可访问;路由守卫 `auth-guard` 校验。

### 3.3 菜单激活态

`nav-team-collapsible.vue` 的 `isActive` 改为**前缀匹配**(`pathname === url || pathname.startsWith(url + '/')`),使详情子页(如专题文章 `/neighborhood/special/[code]/article`)能激活父级菜单(专题管理),保持"服务管理 ▾"展开 + "专题管理"高亮。

## 五、公共组件与模板

### 5.1 RichTextEditor(富文本编辑器)

`src/components/prop-ui/rich-text/`

基于 **Tiptap v3**(headless,与 shadcn 风格一致),全局自动注册。3 处复用(活动/资讯动态/专题文章的 content 字段)。

**功能:** 撤销重做 · 标题下拉(H1-3) · 加粗/斜体/下划线/删除线 · 有序/无序/**任务列表** · **引用块** · 左/中/右/**两端对齐** · **字体颜色/背景色**(色板) · 链接 · 图片(走 `useUpload` 上传 OSS)。

**关键技术点:**
- `v-model` 输出/回填 HTML,对接后端 `content`
- content 字段用**受控同步**(`:model-value` + `@update:model-value` → `setFieldValue`),绕开 vee-validate 只读 `values` 写回问题
- 工具栏用 `ToolbarButton` 子组件(shadcn Button + `type="button"` + 条件 class),不用 reka-ui Toggle(其受控 `pressed` 单向绑定不更新视觉)
- `TextStyle` 扩展必须先于 `Color` 注册(Color 依赖它写 `style` 属性)
- 激活态:监听 `transaction` 事件递增响应式计数器,`isActive` 读它成为响应式依赖,选区变化实时刷新
- 详情查看用 `v-html` 渲染 + `.rich-text-render` 样式块(非 scoped)

### 5.2 CRUD 模板(三种形态)

1. **表格 CRUD**(公告/活动列表/广告/资讯/栏目/专题文章/居委会服务)—— data-table + Dialog 查看 + Sheet 编辑 + AlertDialog 删除
2. **卡片列表 CRUD**(活动分类/服务热线)—— 卡片网格 + Sheet 编辑 + AlertDialog 删除(无查看,卡片已展示全部)
3. **纯列表**(在线留言)—— data-table + Dialog 查看(无增删改)

### 5.3 Copy(复制)

`src/components/prop-ui/copy/Copy.vue`,基于 `@vueuse/core` 的 `useClipboard`,带 tooltip。服务热线卡片、在线留言详情用于复制电话号码。

### 5.4 DateTimePicker

`src/components/prop-ui/date-picker/DateTimePicker.vue`,无值时秒默认 `00`(不再停在当前真实秒);`timePicker` prop 控制精度(传 `{ second: false }` 隐藏秒列,触发器文字跟随精度)。

## 六、关键技术决策

### 6.1 居委会菜单独立分流

`use-sidebar.ts` 在 `merchantSelfNavData` 内按 `userType===6` 分流:居委会返回"居委会后台"菜单组,商户/物业保持原菜单。不污染共享的 merchant 表单。

### 6.2 代客进入跳转分流

`use-proxy-entry.ts` / `use-auth.ts` / `auth-guard.ts` 三处按 `userType===6` 跳 `/neighborhood/home`(居委会后台首页),不再误跳商户概览(`/merchant-business/overview`,其 `roles=[3,4,5]` 不含 6 会 403)。

### 6.3 详情接口 `enabled` 双条件

```ts
enabled: () => (enabled?.value ?? true) && !!uniqueCode.value
```
组件传 `isOpen`,弹层打开**且** id 有值才请求 —— 避免 row-actions 常驻挂载的详情组件在列表加载时即触发请求(`/detail?uniqueCode=undefined`)。

### 6.4 列表接口选择

- 普通列表:`/page` + 分页组件
- 卡片列表(活动分类/服务热线):`/page` + `pageSize=99` 一次拉全量,不分页
  - 原因:`/cate/all` 后端只返回启用的,管理需看全部(含禁用)

### 6.5 站长侧居委会创建/编辑独立组件

`src/pages/committees/` 独立 `committee-form` + Sheet,调专用接口 `POST/PUT /station/neighborhood`(非商户通用的 `/station/merchant`),含居委会特有 `merchantCode`(新建必填/编辑只读)/ `serveResidents` / `members`。不碰共享的 `merchant-form.vue`,商户/物业零影响。

### 6.6 type 驱动字段显隐

广告(3.4)、栏目(3.6)、居委会服务(3.11)各有 `type` 枚举,表单按 type 动态显示对应字段:
- 广告:7=H5/8=专题/11=百度小程序/27=小程序 → resCode 提示变化
- 栏目:附录 B.3 全 11 种
- 居委会服务:7=H5(h5Url)/8=专题(resCode)/27=小程序(appId/originalAppId/bdAppKey)

payload 按类型裁剪,只传相关字段。

### 6.7 专题管理 → 专题文章联动

专题管理点名称跳 `/neighborhood/special/[specialCode]/article`。`columns` 改为 `createColumns(specialCode)` 工厂函数(把 specialCode 传给 row-actions),列表按 specialCode 过滤。跳转用 `RouterLink`(不能在 `.ts` 模块顶层调 `useRouter()`)。
