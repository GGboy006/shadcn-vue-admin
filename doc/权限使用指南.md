# 权限使用指南

## 概述

项目采用**两级权限控制**：

1. **UI 层（菜单过滤）** — 控制侧边栏显示哪些菜单
2. **路由层（守卫拦截）** — 阻止无权限用户直接访问 URL

用户类型定义：

| userType | 角色 | 说明 |
|---------|------|------|
| 3 | 站长 | 小区站长 |
| 4 | 商户 | 商户用户 |
| 5 | 物业 | 物业用户 |

---

## 第一级：UI 层菜单过滤

### 位置

`src/composables/use-sidebar.ts`

### 原理

菜单配置项支持 `roles` 字段，过滤时检查当前用户的 `userType`：

```ts
const allSettingsNavItems = [
  { title: '个人资料', url: '/settings/', icon: UserIcon },
  { title: '站长信息', url: '/settings/account', icon: WrenchIcon, roles: [3] },
]

const settingsNavItems = allSettingsNavItems.filter((item) => {
  if (!item.roles) return true                    // 无 roles → 所有人可见
  return userType !== undefined && item.roles.includes(userType)
})
```

### 效果

- 站长（userType=3）：看到"个人资料" + "站长信息"
- 商户（userType=4）：只看到"个人资料"
- 物业（userType=5）：只看到"个人资料"

## 第二级：路由层守卫拦截

### 位置

`src/router/guard/auth-guard.ts`

### 原理

在页面文件顶部用 `<route>` 块声明需要的角色：

```vue
<!-- src/pages/settings/account.vue -->
<route lang="yaml">
meta:
  roles: [3]
</route>
```

路由守卫读取 `to.meta.roles`，检查当前用户是否匹配：

```ts
router.beforeEach((to) => {
  const userType = authStore.userInfo?.userType
  const requiredRoles = to.meta.roles as number[] | undefined

  if (requiredRoles && (!userType || !requiredRoles.includes(userType))) {
    return { path: '/errors/403' }   // 无权限 → 403 页面
  }
})
```

### 执行顺序

```
用户访问 /settings/account
    │
    ▼
路由守卫：是否登录？
    ├── 未登录 ──→ 跳转到登录页
    │
    └── 已登录
            │
            ▼
        页面需要 roles: [3]？
            ├── userType = 3 ──→ 正常进入
            ├── userType = 4 ──→ 跳转到 403
            └── userType = 5 ──→ 跳转到 403
```

## 如何给页面加权限

### 单角色限制

只允许站长访问：

```vue
<script setup>
// 页面逻辑...
</script>

<template>
  <!-- 页面模板... -->
</template>

<route lang="yaml">
meta:
  roles: [3]
</route>
```

### 多角色限制

允许站长和商户访问：

```vue
<route lang="yaml">
meta:
  roles: [3, 4]
</route>
```

### 不加权限

不写 `<route>` 块或只写布局：

```vue
<route lang="yaml">
meta:
  layout: default
</route>
```

## 菜单与路由的权限对应

**两者必须保持一致**，否则会出现菜单看不到但 URL 能访问，或者菜单看得到但访问被拦的情况。

正确示例：

```ts
// use-sidebar.ts
{ title: '站长信息', url: '/settings/account', icon: WrenchIcon, roles: [3] }
```

```vue
<!-- account.vue -->
<route lang="yaml">
meta:
  roles: [3]
</route>
```

## 登录与权限的状态来源

用户信息存在 Pinia Store 中：

```ts
// src/stores/auth.ts
const userInfo = ref<LoginUserVO | null>(null)

interface LoginUserVO {
  nickname: string
  avatar: string
  gender: number
  phone: string
  userType: number   // ← 权限判断的关键字段
}
```

获取用户类型：

```ts
const authStore = useAuthStore()
const userType = authStore.userInfo?.userType
// 或
const userType = authStore.getUserType()
```

## 常见权限场景

### 场景 1：按钮级权限

页面内某些按钮只对特定角色显示：

```vue
<template>
  <Button v-if="userType === 3">站长专属操作</Button>
</template>

<script setup>
const authStore = useAuthStore()
const userType = authStore.getUserType()
</script>
```

### 场景 2：表格列权限

不同角色看到不同的表格列：

```vue
<template>
  <Table>
    <TableColumn title="姓名" />
    <TableColumn title="手机号" />
    <TableColumn v-if="userType === 3" title="站长备注" />
  </Table>
</template>
```

### 场景 3：表单字段权限

不同角色可编辑不同字段：

```vue
<template>
  <Input v-model="form.name" :disabled="userType !== 3" />
</template>
```

## 权限配置速查表

| 需求 | 菜单配置 | 路由配置 | 说明 |
|------|---------|---------|------|
| 所有人可见 | 不写 `roles` | 不写 `<route>` 或只写 `layout` | 默认 |
| 仅站长可见 | `roles: [3]` | `roles: [3]` | 菜单和路由都限制 |
| 站长+商户可见 | `roles: [3, 4]` | `roles: [3, 4]` | 多角色 |
| 仅 UI 隐藏 | `roles: [3]` | 不写 `roles` | 菜单看不到，但 URL 能访问 |
| 仅路由拦截 | 不写 `roles` | `roles: [3]` | 菜单能看到，但进不去 |

## 扩展：动态权限（第二阶段）

当前权限是**硬编码**的（代码里写死 userType 对应哪些菜单）。

如果需要后端动态配置权限（比如管理员后台配置"哪个角色能访问哪个页面"），则需要：

1. 后端提供权限接口，返回角色-菜单映射
2. 前端登录时获取权限列表
3. 菜单和路由守卫都读取权限列表做判断
4. 通常使用 `permission: ['station:info', 'user:list']` 这种字符串权限码

此功能在第一阶段不做，第二阶段规划。
