# 三端工作台 · 后端接口开发清单

> 背景：站长 /dashboard、商户/物业 /merchant-business/overview、居委会 /neighborhood/home 三端工作台前端页面已全部开发完成，当前均用固定 Mock 数据渲染。本文档汇总全部需要后端确认/新增的接口，供排期与对接。

> - 前端类型定义：src/services/api/workbench.api.ts
> - 已有汇总接口规范：doc/CityData工作台汇总接口.md

## 一、总体接口约定

- 每端只有 1 个对外接口，前端进入页面只发 1 次请求：

  | 端 | 前端页面 | 汇总接口(路径待后端确认 BFF 转发路径) |
  |---|---|---|
  | 站长 | /dashboard（4 个 Tab：概览/商户/小区服务/居委会） | stationSummary |
  | 商户/物业 | /merchant-business/overview（单页，物业与商户共用同一套） | merchantSummary |
  | 居委会 | /neighborhood/home（单页） | orgSummary |

- 每个接口内部由后端聚合：City Data 汇总（已有规范）+ 本库统计（本文档标"需新增"的部分），前端侧不拆分请求。
- 若字段短期内无法全部提供，可按优先级排期，未就绪字段前端会用 0 / [] 兜底展示，不阻断页面。

## 二、站长工作台（stationSummary）

站长最关心"签约"而非商户订单收入，"概览"Tab 的核心指标围绕签约展开。

### 1. 概览 Tab

| 字段 | 类型 | 说明 | 现状 | 优先级 |
|---|---|---|---|---|
| signAnalysis | {type,typeName,count,amount}[] | 按签约方类型（商户/居委会/物业）拆分的签约数量与金额 | 需新增 | P0 |
| signTrend | {month,merchant,org,property}[] | 近 6 个月新签约趋势，按类型拆分 | 需新增 | P0 |

### 2. 商户 Tab

| 字段 | 类型 | 说明 | 现状 | 优先级 |
|---|---|---|---|---|
| totalOrderAmount | number | 区间内商户订单总额 | 已有 | - |
| incomeAnalysis | {merchantCode,merchantName,totalAmount,orderCount}[] | 商户收入排行 | 已有 | - |
| merchantGoodsCount/merchantFaqCount/merchantActivityCount | number | 商户商品/FAQ/活动总数 | 已有 | - |
| orderTrend | {day,thisWeek,lastWeek}[] | 近 7 日订单量趋势(本周 vs 上周同期) | 需新增 | P1 |
| merchantAiConversationCount/merchantAiImageGenerationCount | number | 商户端 AI 对话/生图次数(近 30 天) | 需新增 | P2 |

### 3. 小区服务 Tab

| 字段 | 类型 | 说明 | 现状 | 优先级 |
|---|---|---|---|---|
| noticeCount/dynamicPendingCount/servicePendingCount/communityGoodsPendingCount/secondhandPendingCount | number | 公告总数/动态待审/服务待启用/商品待启用/闲置待审 | 已有 | - |
| feedbackPendingCount | number | 意见反馈待处理数 | 需确认 /community/feedback 是否已有 count 接口 | P1 |
| residentAiConversationCount/residentAiImageGenerationCount | number | 居民端 AI 对话/生图次数(近 30 天，对应侧边栏"居民 AI 工具") | 需新增 | P2 |

### 4. 居委会 Tab

| 字段 | 类型 | 说明 | 现状 | 优先级 |
|---|---|---|---|---|
| leaveMessagePendingCount | number | 留言待处理合计(跨名下居委会汇总) | 已有 | - |
| orgAnalysis | {orgCode,orgName,signAmount,leaveMessagePending}[] | 名下居委会明细(签约金额+留言待处理排行)，City Data 目前只有汇总值，需按 orgCode 拆分 | 需新增 | P1 |

## 五、需新增字段的实现建议

| 字段 | 涉及端 | 建议实现 |
|---|---|---|
| signAnalysis | 站长 | 按 type(merchant/org/property)分组 COUNT+SUM(签约费)；物业和商户若同表用 bizType 区分 |
| signTrend | 站长 | 按签约时间(月)+type 分组 COUNT，返回近 6 个月，缺失月份补 0 |
| orderTrend | 站长/商户 | 返回近 14 天(本周 7 天+上周同期 7 天)按天分组的订单量，前端按星期对齐成 thisWeek/lastWeek |
| orgAnalysis | 站长 | 按 orgCode 分组 COUNT(留言待处理)；签约金额从签约表按 orgCode 关联 |
| merchantAiConversationCount/merchantAiImageGenerationCount | 站长 | 按业务类型(商户相关 AI 工具/数字员工)过滤统计，近 30 天 |
| residentAiConversationCount/residentAiImageGenerationCount | 站长 | 按业务类型(居民 AI 工具)过滤统计，近 30 天；需与商户端统计口径区分开 |
| housekeepingOrderCount/procurementOrderCount/conversationCount | 商户 | 分别统计家政工单表、智采订单表、数字员工对话记录表(近 30 天) |
| knowledgeReadCount/aiConversationCount | 居委会 | 知识服务阅读日志、AI 对话记录按 orgCode 统计(近 30 天) |
| feedbackPendingCount | 站长/居委会 | 若现有反馈模块已有统计接口，直接复用；否则新增 |

## 七、待后端确认的问题

1. residential-web 侧的 BFF 转发路径(前端直接调用哪个 URL，不是 City Data 内部路径)，三端各 1 个。
2. partnerId/merchantCode/orgCode 是否由后端从当前登录 token 自动解析？前端已按"无需手动传参"实现，若仍需前端传，请告知参数名与来源。
3. 时间字段格式(yyyy-MM-dd HH:mm:ss 还是时间戳)。
4. signAnalysis/signTrend 依赖的签约表结构：字段名(type/bizType)、签约费字段名、签约时间字段名。
5. "需新增"字段建议按 P0 -> P1 -> P2 排期，P0 只有站长"概览"的 2 个签约字段，优先级最高；其余字段未就绪时前端按 0/[] 兜底展示，不阻断页面。
