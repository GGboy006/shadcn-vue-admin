## 0. 通用说明

### 0.1 认证

所有接口需在请求头携带 Token：

```http
Authorization: {token}
```

> 实际环境以登录接口返回的 token 为准；Knife4j 调试时 header 名为 `authorization`。

### 0.2 角色与权限

| 角色 | userType | 能力范围 |
|------|----------|----------|
| 小区站长 | 3 | 名下居委会的增删改查、启停；路径前缀 `/station` |
| 居委会管理员 | 6 | 本居委会资料维护 + 全部内容管理；路径前缀 `/neighborhood`；`orgCode` 由后端按当前登录用户自动注入 |

### 0.3 统一响应 `BaseResponse<T>`

```json
{
  "code": 0,
  "level": null,
  "msg": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | Integer | `0`=成功，其他为错误码 |
| level | String\|null | 错误级别（可空） |
| msg | String | 提示信息 |
| data | T | 业务数据 |

### 0.4 分页请求 `PageParam`

GET Query 传参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | Long | 是 | 页码，从 1 开始 |
| pageSize | Long | 是 | 每页条数，最大 200 |
| searchCount | Boolean | 否 | 是否查询总条数 |

### 0.5 分页响应 `PageResult<T>`

```json
{
  "pageNum": 1,
  "pageSize": 10,
  "total": 100,
  "pages": 10,
  "list": [],
  "emptyFlag": false
}
```

### 0.6 对接约定（前端 / LLM 必读）

1. **`orgCode` / `merchantCode`（城市侧）**：居委会内容类接口由后端自动注入，请求体**不要传**或传了也会被覆盖。
2. **`uniqueCode`**：内容资源的业务主键，更新 / 删除 / 详情均依赖此字段。
3. **时间格式**：`yyyy-MM-dd HH:mm:ss`（LocalDateTime）；日期格式：`yyyy-MM-dd`（LocalDate）。
4. **Long 型 ID**：JSON 中可能以字符串形式返回（雪花 ID），前端按字符串处理更安全。
5. **居委会类型常量**：`type = 6`（`USER_TYPE_MERCHANT_RESIDENT`）。
6. **站长新增居委会**：通过城市库已有 `merchantCode`（城市居委会标识）绑定，后端会拉取城市居委会信息生成本地账号。
7. **登录**：居委会管理员（userType=6）登录与商户登录一致，站长代客登录逻辑也相同，复用现有登录接口，本文档不再单独列出。

### 0.7 居委会侧前端菜单结构

居委会管理员（userType=6）登录后的左侧导航结构如下（顺序与 [第三章](#三居委会侧--内容管理) 各内容管理接口一致）：

```text
- 首页                        // 暂时空白,无接口和页面,仅占位
- 公告管理                    // 3.1 notice
- 活动管理                    // 父级,展开两个子菜单(父级本身无独立页面)
  ├─ 活动分类                  // 3.2 cate
  └─ 活动列表                  // 3.3 activity
- 广告管理                    // 3.4 banner
- 资讯动态                    // 3.5 dynamic
- 服务管理                    // 父级,展开两个子菜单(父级本身无独立页面)
  ├─ 栏目管理                  // 3.6 unified
  └─ 专题管理                  // 3.7 special
- 居委会信息                  // 2.1 / 2.2 基础信息(单独菜单,位于服务热线上方)
- 服务热线                    // 3.9 serviceGuide
- 在线留言                    // 3.10 leaveMessage(仅列表)
- 居委会服务                  // 3.11 service
```

**说明**：

1. **首页**：暂未提供接口与页面，前端先建 `/neighborhood/home` 空页面占位，接口后补。
2. **活动管理**、**服务管理**为二级菜单父级，点击展开后显示对应子菜单，父级本身无独立页面。
3. **专题文章**（3.8 `specialArticle`）**不在菜单中**：它是“专题管理”列表项点击后进入的详情子页面，归属于专题管理之下。
4. 其余菜单项均为一级菜单，对应 [第三章](#三居委会侧--内容管理) 各内容管理接口。
5. **居委会信息**（[2.1](#21-查看居委会信息) / [2.2](#22-更新居委会信息)）：单独菜单项，位于“服务热线”上方，用于居委会管理员维护本居委会资料。

## 一、站长侧 · 居委会管理

> 控制器：`BusinessStationMasterController`  
> 基础路径：`/station`  
> 身份：小区站长（userType=3）

### 1.1 分页列表

- **Method / Path**：`GET /station/merchant/page`
- **说明**：查询名下商户/物业/居委会；查居委会时固定传 `type=6`

**Query 参数** `BusinessMerchantPageDTO`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | Integer | 否 | **居委会传 `6`**；4=商户，5=物业 |
| merchantName | String | 否 | 名称模糊（同时匹配联系人） |
| signStatus | Integer | 否 | 签约状态：1=已签约，2=未签约 |
| pageNum | Long | 是 | 页码 |
| pageSize | Long | 是 | 每页条数 |

**响应 data**：`PageResult<BusinessMerchantListVO>`

| 字段 | 类型 | 说明 |
|------|------|------|
| merchantId | Long | 居委会本地 ID |
| nickname | String | 管理员昵称 |
| phone | String | 登录手机号 |
| merchantCode | String | 城市居委会标识 |
| merchantName | String | 居委会名称 |
| logo | String | Logo |
| stationUserId | Long | 所属站长用户 ID |
| type | Integer | 6=居委会 |
| contactName | String | 联系人 |
| contactPhone | String | 联系电话 |
| signDate | LocalDate | 签约日期 |
| signFee | BigDecimal | 签约费用 |
| serveResidents | Integer | 服务居民数 |
| members | Integer | 成员数 |
| status | Integer | 1=启用，2=禁用 |

**调用示例**

```http
GET /web/station/merchant/page?type=6&pageNum=1&pageSize=10
Authorization: {token}
```

---

### 1.2 详情

- **Method / Path**：`GET /station/merchant/{merchantId}`
- **说明**：居委会详情（与商户/物业共用详情接口）

**Path 参数**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| merchantId | Long | 是 | 居委会本地 ID |

**响应 data**：`BusinessMerchantVO`（见 [附录 A.1](#a1-businessmerchantvo)）

---

### 1.3 新增

- **Method / Path**：`POST /station/neighborhood`
- **说明**：绑定城市居委会并创建本地管理员账号；名称/手机号/密码/Logo 等从城市库拉取

**请求体** `BusinessOrgAddDTO`（`Content-Type: application/json`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| merchantCode | String | **是** | 城市居委会标识（绑定用）；**由站长手动粘贴输入**，无候选列表接口 |
| nickname | String | **是** | 本地管理员昵称 |
| avatar | String | 否 | 头像 URL |
| gender | Integer | 否 | 0=未知，1=男，2=女 |
| contactName | String | 否 | 联系人 |
| contactPhone | String | 否 | 联系电话 |
| address | String | 否 | 详细地址 |
| signDate | LocalDate | 否 | 签约日期 |
| signFee | BigDecimal | 否 | 签约费用 |
| serveResidents | Integer | 否 | 服务居民数，默认 0 |
| members | Integer | 否 | 成员数，默认 0 |
| remark | String | 否 | 简介；为空时用城市库简介 |
| status | Integer | 否 | 1=启用，2=禁用 |

**请求示例**

```json
{
  "nickname": "西小营",
  "avatar": "https://example.com/avatar.jpg",
  "gender": 1,
  "merchantCode": "3ssd10ab5a3947ca9lsadjhkf25b9c1250",
  "contactName": "办公室工作人员",
  "contactPhone": "010-89422719",
  "address": "北京市顺义区复康街1号",
  "signDate": "2026-07-31",
  "signFee": 0,
  "serveResidents": 1468,
  "members": 10,
  "remark": "",
  "status": 1
}
```

**响应 data**：`Boolean`（`true` 表示成功）；新增成功后不返回 `merchantId`，前端通过列表刷新定位新记录。

**业务约束**

- `merchantCode` 必须在城市库存在，否则报错。
- 同一 `merchantCode` 不可重复绑定。
- 城市库手机号若本地已存在，报手机号重复。
- `merchantCode` 无候选列表接口，由站长从城市库复制后手动填入输入框。

## 二、居委会侧 · 基础信息

> 控制器：`BusinessOrgController`  
> 基础路径：`/neighborhood`  
> 身份：居委会管理员（userType=6）  
> 说明：`orgCode` 一律由后端根据当前登录用户解析，前端无需传递。

### 2.1 查看居委会信息

- **Method / Path**：`GET /neighborhood/myOrgInfo`
- **说明**：返回当前登录居委会管理员绑定的居委会详情

**请求参数**：无

**响应 data**：`BusinessMerchantVO`（见 [附录 A.1](#a1-businessmerchantvo)）

**调用示例**

```http
GET /web/neighborhood/myOrgInfo
Authorization: {token}
```

---

### 2.2 更新居委会信息

- **Method / Path**：`PUT /neighborhood/updateMyOrgInfo`
- **说明**：居委会管理员更新本居委会资料，并同步城市 `updateOrg`

**请求体** `BusinessOrgUpdateDTO`（字段同 [1.4](#14-更新)）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| merchantId | Long | **是** | 必须等于当前登录用户所属居委会 ID |
| 其余字段 | — | 否 | 同站长更新；`password` 为空不修改 |

**响应 data**：`Boolean`

**业务约束**

- `merchantId` 必须与当前登录用户绑定的居委会一致，否则无权限。
- 非 `type=6` 数据不可通过此接口更新。

## 三、居委会侧 · 内容管理

> 以下接口均在 `/neighborhood` 下，由当前登录居委会身份鉴权。  
> 列表类统一支持可选 `keyword` + `PageParam`。  
> 删除统一：`DELETE /neighborhood/{资源}/{uniqueCode}`。

### 3.1 公告管理

| 操作 | Method | Path |
|------|--------|------|
| 分页列表 | GET | `/neighborhood/notice/page` |
| 详情 | GET | `/neighborhood/notice/detail?uniqueCode=` |
| 新增 | POST | `/neighborhood/notice` |
| 更新 | PUT | `/neighborhood/notice` |
| 删除 | DELETE | `/neighborhood/notice/{uniqueCode}` |

#### 列表 Query

| 字段 | 类型 | 必填 | 说明 |

| pageNum / pageSize | Long | 是 | 分页 |

**响应 data**：`PageResult<CommunityNoticeVO>`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键 |
| uniqueCode | String | 唯一标识 |

| introduction | String | 简介 |

| contentType | Integer | 1=文本，2=链接 |

| torder | Integer | 排序 |
| partnerId | String | 合伙人标识 |
| createTime / updateTime | LocalDateTime | 时间 |

#### 详情响应

#### 新增/更新请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

| contentType | Integer | 否 | 1=文本，2=链接 |
| content | String | 否 | 正文（文本时） |
| h5Url | String | 否 | 跳转链接（链接时） |
| isPublic | Integer | 否 | 1=公有，2=私有 |
| resCode | String | 否 | 关联内容 |
| torder | Integer | 否 | 排序 |
| orgCode | String | 否 | **后端注入，勿传** |

**更新** `CompanyNoticeUpdateReq` = 新增字段 + `uniqueCode`（**必填**）
