## 各目录详解

### components/ui/

shadcn-vue 组件库，源码级引入。**所有组件都在项目里**，可直接修改。

```
components/ui/
├── badge/          # Badge 徽章组件
│   ├── Badge.vue   #   组件本体
│   └── index.ts    #   样式变体定义 + 导出
├── button/
├── input/
├── form/           # 表单相关（FormField、FormItem、FormLabel...）
└── ...
```

### composables/

Vue 3 组合函数，存放可复用的逻辑。

| 文件 | 用途 | 使用方式 |
|------|------|---------|
| `use-auth.ts` | 登录、登出、跳转首页 | `const { login, logout, loading } = useAuth()` |
| `use-fetch.ts` | 封装 ofetch，自动加 token | `const { apiFetch } = useApiFetch()` |
| `use-sidebar.ts` | 侧边栏菜单配置 | `const { navData, settingsNavItems } = useSidebar()` |
| `use-upload.ts` | 文件上传到 OSS | `const { upload, loading } = useUpload()` |

### pages/

**文件系统路由**，不需要手写路由表。

```
pages/
├── index.vue              →  /
├── dashboard.vue          →  /dashboard
├── auth/
│   ├── sign-in.vue        →  /auth/sign-in
│   └── sign-up.vue        →  /auth/sign-up
├── settings/
│   ├── index.vue          →  /settings
│   ├── account.vue        →  /settings/account
│   └── appearance.vue     →  /settings/appearance
└── users/
    └── index.vue          →  /users
```

**约定：**
- `.vue` 文件 = 一个路由页面
- 文件夹 = 路由前缀
- `index.vue` = 文件夹的默认页面
- `components/` 子目录下的文件**不会**生成路由

### layouts/

页面外层布局，在页面中通过 `<route>` 块选择：

```vue
<route lang="yaml">
meta:
  layout: blank    # 使用 layouts/blank.vue
</route>
```

### stores/

Pinia 状态管理，**自动持久化**到 localStorage。

```ts
// 使用
const authStore = useAuthStore()
authStore.setToken('xxx')

// 刷新页面后数据仍在（pinia-plugin-persistedstate）
```

### types/

**自动生成的类型声明文件，不要手动修改。**

| 文件 | 生成来源 |
|------|---------|
| `auto-import.d.ts` | `unplugin-auto-import`（自动导入的函数） |
| `auto-import-components.d.ts` | `unplugin-vue-components`（自动导入的组件） |
| `route-map.d.ts` | `vue-router/unplugin`（路由类型） |

如果新增 composable 或组件后类型报错，重启 dev 服务器重新生成。

## 文件组织约定

### 页面文件结构

```
pages/settings/
├── index.vue               # 设置首页（个人资料）
├── account.vue             # 站长信息页
├── appearance.vue          # 外观设置页
├── components/             # 页面私有组件
│   ├── account-form.vue
│   ├── profile-form.vue
│   └── appearance-form.vue
└── validators/             # 页面级校验规则
    ├── account.validator.ts
    └── profile.validator.ts
```

### 按功能组织，不按类型组织

```
✅ 推荐：按功能分组
pages/settings/
  ├── components/
  └── validators/

❌ 不推荐：按类型分散
components/settings/
validators/settings/
```

### Composable 命名

```ts
// ✅ 推荐：use + 动词/名词
useAuth()
useFetch()
useSidebar()

// ❌ 不推荐
auth()
fetchData()
```

### Store 命名

```ts
// ✅ 推荐：use + 领域 + Store
useAuthStore()
useUserInfoStore()

// 文件命名
stores/auth.ts
stores/user-info.ts
```

## 路由与文件的映射

| 文件路径 | 路由路径 | 布局 |
|---------|---------|------|
| `pages/index.vue` | `/` | default |
| `pages/dashboard.vue` | `/dashboard` | default |
| `pages/auth/sign-in.vue` | `/auth/sign-in` | blank |
| `pages/settings/index.vue` | `/settings` | default |
| `pages/settings/account.vue` | `/settings/account` | default |
| `pages/[...path].vue` | `/*`（404 兜底）| blank |

## 新增页面的标准流程

1. 在 `pages/` 下创建 `.vue` 文件
2. 如需布局切换，在页面顶部加 `<route>` 块
3. 如需角色权限，在 `<route>` 块加 `roles: [3]`
4. 如需加入菜单，在 `use-sidebar.ts` 中配置
5. 如需复用组件，放在页面目录的 `components/` 下

---

## 注意事项

1. **不要手动修改 `types/*.d.ts`** — 这些文件由构建工具自动生成
2. **Composables 必须放在 `composables/` 下** — `unplugin-auto-import` 只扫描这个目录
3. **Store 必须放在 `stores/` 下** — 同上
4. **新增页面后如果路由不对** — 检查是否在 `vite.config.ts` 的 `RouteGenerateExclude` 中被排除了
5. **`public/` 下的文件直接通过根路径访问** — 如 `public/logo.png` → 访问 `/logo.png`
