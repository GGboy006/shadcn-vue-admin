# 站长重新生成功能设计文档

## 1. 概述

### 1.1 背景
商户通过 AI 向导（`[skillId].vue`）选择配置并生成图片后，可能对结果不满意。此时站长在聊天工作台（`chat-workbench.vue`）与商户沟通，了解修改需求后，需要基于商户原有的选择配置（steps）进行重新生成。站长拥有比商户更多的编辑权限，可以在原有配置基础上添加修改意见，生成新图片后直接发送给商户。

### 1.2 目标
- 站长点击"基于此方案重新生成"按钮，跳转到 `[skillId].vue` 页面
- 页面预填充商户原有的 steps 数据，跳过选择步骤直接进入结果展示
- 站长可在结果展示页查看商户原图，添加修改意见并重新生成
- 生成新图片后，站长可输入发送给商户的话并一键发送

## 2. 当前流程分析

### 2.1 `[skillId].vue` 页面流程

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   用户选择步骤   │ --> │   AI生成确认页   │ --> │   结果展示页     │
│  (actionType=1) │     │  (actionType=2) │     │  (actionType=4) │
│  ChoiceGrid/List│     │ GenerationConfirm│    │ ResultPreview   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
        │                       │                       │
        v                       v                       v
   makeChoice()            streamPrompt()          展示图片+操作
   goToNextStep()          轮询生成状态             重新生成/下载
```

### 2.2 关键状态（useWizard）

| 状态 | 类型 | 说明 |
|------|------|------|
| `skillId` | Ref<string> | 技能ID |
| `currentStepCode` | Ref<string> | 当前步骤编码 |
| `currentStepIndex` | Ref<number> | 当前步骤索引 |
| `completedStepCodes` | Ref<string[]> | 已完成步骤编码列表 |
| `userChoices` | Ref<Record<string, any>> | 用户选择数据 |
| `stepForms` | Ref<IWizardStepForm[]> | 步骤表单数据 |
| `chatId` | Ref<string \| null> | 会话ID |
| `generationStatus` | Ref<0 \| 1 \| 2 \| null> | 生成状态 |
| `generatedImageUrl` | Ref<string \| null> | 生成图片URL |
| `isStationMode` | Ref<boolean> | 是否站长模式 |
| `stationModifyPrompt` | Ref<string> | 站长修改意见 |

### 2.3 步骤类型判定

```typescript
// 用户选择步骤
const isUserChoiceStep = computed(() => wizard.currentFlow.value?.actionType === 1)

// AI生成步骤
const isGenerationStep = computed(() => wizard.currentFlow.value?.actionType === 2)

// 完成步骤
const isCompletionStep = computed(() => wizard.currentFlow.value?.actionType === 4)
```

| 环节 | 商户流程 | 站长流程 |

| 结果处理 | 下载/重新生成 | 发送给商户/下载/重新生成 |

## 4. 数据传递机制

### 4.1 传递方式：Pinia Store（推荐）

为避免 URL 参数过长，使用 Pinia store 进行跨页面数据传递：

```typescript
// src/stores/station-regenerate.ts
export const useStationRegenerateStore = defineStore('stationRegenerate', () => {
  const regenerateData = ref<{ chatId: string, steps: IWizardStepForm[] } | null>(null)

  function setRegenerateData(data: { chatId: string, steps: IWizardStepForm[] }) {
    regenerateData.value = data
  }

  function getRegenerateData() {
    const data = regenerateData.value
    regenerateData.value = null  // 读取后自动清理
    return data
  }

  return { regenerateData, setRegenerateData, getRegenerateData }
}, { persist: false })  // 不持久化到 localStorage
```

### 4.2 URL 格式

仅携带模式标记，数据通过 store 传递：

```
/apps/{skillId}?mode=station_regenerate
```

### 4.3 数据流转

```
chat-workbench.vue                          [skillId].vue
     │                                           │
     │  1. 从 msg 提取数据                         │
     │     - msg.steps (IWizardStepForm[])         │
     │     - msg.chatId (string)                   │
     │     - conversation.skillId (string)         │
     │                                           │
     │  2. 存入 Pinia store                        │
     │     stationStore.setRegenerateData({        │
     │       chatId, steps                         │
     │     })                                      │
     │                                           │
     │  3. 跳转（仅携带 mode）                      │
     │     router.push({                          │
     │       path: `/apps/${skillId}`,            │
     │       query: { mode: 'station_regenerate' }│
     │     })                                     │
     │------------------------------------------>│
     │                                           │
     │                                           │  4. 检测 mode
     │                                           │     const mode = route.query.mode
     │                                           │
     │                                           │  5. 从 store 读取数据
     │                                           │     const data = stationStore.getRegenerateData()
     │                                           │
     │                                           │  6. 初始化向导状态
     │                                           │     wizard.initWithStationData({ chatId, steps })
```

## 6. 状态管理扩展

### 6.1 useWizard 扩展

```typescript
// ==================== 站长重新生成模式 ====================

/** 是否处于站长重新生成模式 */
const isStationMode = ref(false)

/** 站长修改意见 */
const stationModifyPrompt = ref('')

/**
 * 使用站长数据初始化向导
 * @param params.chatId 原会话ID
 * @param params.steps 商户选择的步骤数据
 */
function initWithStationData(params: { chatId: string, steps: IWizardStepForm[] }) {
  if (!skillDetail.value || skillDetail.value.flows.length === 0) return

  const { chatId: initChatId, steps } = params

  // 设置站长模式
  isStationMode.value = true
  stationModifyPrompt.value = ''

  // 设置会话ID
  chatId.value = initChatId

  // 设置步骤表单
  stepForms.value = steps

  // 设置已完成步骤
  completedStepCodes.value = steps.map(s => s.stepCode)

  // 重建用户选择
  const choices: Record<string, any> = {}
  steps.forEach((step) => {
    step.fieldValues.forEach((fv) => {
      choices[fv.field] = fv.value
    })
  })
  userChoices.value = choices

  // 初始化所有步骤的表单结构
  skillDetail.value.flows.forEach((flow) => {
    initStepForm(flow)
  })

  // 跳转到最后一步（完成步骤/actionType=4）
  const completionFlow = skillDetail.value.flows.find(f => f.actionType === 4)
  if (completionFlow) {
    currentStepCode.value = completionFlow.stepCode
    currentStepIndex.value = skillDetail.value.flows.findIndex(
      f => f.stepCode === completionFlow.stepCode,
    )
  }

  // 设置生成状态为成功（因为商户已经生成过）
  generationStatus.value = 1
  isGenerating.value = false
  isProcessing.value = false
}

/** 重置站长模式 */
function resetStationMode() {
  isStationMode.value = false
  stationModifyPrompt.value = ''
}
```

## 7. 类型定义

### 7.1 IWizardStepForm（flowId 为 string）

```typescript
export interface IWizardStepForm {
  /** 流程节点ID */
  flowId: string
  /** 步骤编码 */
  stepCode: string
  /** 步骤名称 */
  stepName: string
  /** 该步骤的所有字段选择 */
  fieldValues: IWizardFieldValue[]
}
```

> **注意**：后端 `ISkillFlow.flowId` 为 `number`，但消息中的 `flowId` 为 `string`。前端在 `initStepForm` 中使用 `String(flow.flowId)` 进行转换，确保与消息数据类型一致。

### 7.2 IWizardSubmitForm

```typescript
export interface IWizardSubmitForm {
  skillId: string
  chatId: string | null
  steps: IWizardStepForm[]
  /** 站长修改意见（可选） */

}
```
