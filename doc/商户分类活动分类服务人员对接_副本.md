# 商户分类 / 优惠活动分类 / 服务人员对接文档

> **适用端**：站长工作台 PC（`/station`）、商户后台（`/merchant`）、管家服务（`/housekeeper`）  
> **Base URL**：`https://content.icitychina.net/residential-web/web`  
> **鉴权**：`Authorization: Bearer {token}`  
> **统一响应**：`{ code, level, msg, data }`，成功 `code = 0`  
> **关联下游**：数字城市 city-api（`data/station/...`），由后端代理调用，前端只调本服务

## 1. 概念与数据关系

| 能力 | 谁管理 | 表 / type | 选择字段 | 说明 |
|------|--------|-----------|----------|------|
| 商户分类 | 站长 | `tbl_coupon_category`（type=2 商户） | `categoryCode` | 给商户打标签，新增/编辑商户时下拉选择 |
| 优惠活动分类 | 商户 | `tbl_app_enterprise_cate`（type=1 活动） | `cateCode` + `cateName` | 与商品分类同表，商品分类 type=2 |
| 服务人员 | 站长（管家） | 本地 `owner_housekeeper_staff` + 本地用户 | `phone` | 新增/更新时同步数字城市 APP 用户 |

```
站长维护商户分类
    └─ 新增/编辑商户时选择 categoryCode
         └─ 同步到城市数据中心商户

商户维护优惠活动分类（type=1）
    └─ 新增/编辑优惠活动时选择 cateCode / cateName

站长维护服务人员
    └─ 校验手机号 → 同步 city-api /station/synAppUser → 本地开通 userType=8 账号
```

## 2. 商户分类（站长端）

**后端**：`BusinessStationMasterController`  
**路径前缀**：`/station/merchant/category`  
**说明**：`partnerId` 由当前站长 `stationCode` 自动注入，前端无需传。

### 2.1 分页列表

`GET /station/merchant/category/page`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| keyword | query | String | 否 | 分类名称模糊 |
| pageNum | query | Long | 是 | 页码 |
| pageSize | query | Long | 是 | 每页条数 |

**响应** `PageResult<TblCouponCategoryResp>`

| 字段 | 类型 | 说明 |
|------|------|------|
| uniqueCode | String | 分类唯一标识（即商户侧 `categoryCode`） |
| name | String | 分类名称 |
| torder | Integer | 排序 |
| status | Integer | 1=启用，2=禁用 |
| type | Integer | 固定为商户分类 |
| layoutType | Integer | 布局：1美团 2饿了么 3滴滴 4快递100 |
| partnerId | String | 合伙人ID |
| createTime / updateTime | LocalDateTime | 时间 |

### 2.2 全部（下拉）

`GET /station/merchant/category/list`

**响应** `List<TblCouponCategoryResp>`（已启用，用于商户新增/编辑下拉）

### 2.3 新增

`POST /station/merchant/category`

```json
{
  "name": "餐饮",
  "torder": 1,
  "status": 1,
  "layoutType": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | 分类名称 |
| torder | Integer | 否 | 排序 |
| status | Integer | 否 | 1=启用，2=禁用 |
| layoutType | Integer | 否 | 布局类型 |

**响应** `String`（`uniqueCode`）

### 2.4 更新

`PUT /station/merchant/category`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| uniqueCode | String | 是 | 分类标识 |
| name | String | 是 | 分类名称 |
| torder / status / layoutType | | 否 | 同新增 |

**响应** `Boolean`

### 2.5 删除

`DELETE /station/merchant/category/{uniqueCode}`

**响应** `Boolean`

## 3. 商户新增/更新选择分类

**后端**：`BusinessStationMasterController`  
**路径**：`POST /station/merchant`、`PUT /station/merchant`

### 3.1 选择流程

1. 先调 `GET /station/merchant/category/list` 拉已启用分类  
2. 用户选择后，把对应 `uniqueCode` 写入请求体 `categoryCode`  
3. 详情回显：`GET /station/merchant/{merchantId}` 返回 `categoryCode`

### 3.2 新增 Body 关键字段

`POST /station/merchant` → `BusinessMerchantAddDTO`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| categoryCode | String | 否 | 商户分类标识，来自分类 `uniqueCode` |
| nickname / phone / password / merchantName / type | | 是 | 基础账号与商户信息 |
| type | Integer | 是 | 4=商户，5=物业 |

> 居委会走独立接口 `/station/neighborhood`，不在此选商户分类。

### 3.3 更新 Body 关键字段

`PUT /station/merchant` → `BusinessMerchantUpdateDTO`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| merchantId | Long | 是 | 商户ID |
| categoryCode | String | 否 | 商户分类标识；传空/不传按后端更新策略处理 |
| type | Integer | 是 | 4=商户，5=物业 |

### 3.4 详情回显

`GET /station/merchant/{merchantId}` → `BusinessMerchantVO.categoryCode`

前端可用 `categoryCode` 在下拉选项中回选名称。

## 4. 优惠活动分类（商户端）

**后端**：`BusinessMerchantController`  
**路径前缀**：`/merchant/activity/cate`  
**数据**：`tbl_app_enterprise_cate`，`type=1`（企业活动）  
**鉴权**：路径 `merchantId`，商户本人或所属站长可操作

> 注意：`/merchant/cate/...` 是**商品分类**（type=2），不要和本模块混淆。

### 4.1 全部（下拉）

`GET /merchant/activity/cate/{merchantId}/all`

**响应** `List<TblAppEnterpriseCateResp>`

| 字段 | 类型 | 说明 |
|------|------|------|
| uniqueCode | String | 分类标识（活动侧 `cateCode`） |
| orgCode | String | 商户编码 |
| name | String | 分类名称 |
| type | Integer | 1=企业活动 |
| torder | Integer | 排序 |
| isEnable | Integer | 1=启用，2=禁用 |

### 4.2 分页列表

`GET /merchant/activity/cate/{merchantId}/page`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| pageNum / pageSize | query | Long | 是 | 分页 |

**响应** `PageResult<TblAppEnterpriseCateVO>`

| 字段 | 类型 | 说明 |
|------|------|------|
| uniqueCode | String | 分类标识 |
| orgCode | String | 商户编码 |
| name | String | 名称 |
| torder | Integer | 排序 |
| isEnable | Integer | 启用状态 |
| activityCount | Long | 分类下活动数量 |

### 4.3 新增

`POST /merchant/activity/cate/{merchantId}`

```json
{
  "name": "满减活动",
  "torder": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | 分类名称 |
| torder | Integer | 否 | 排序 |

> `merchantCode` 由后端按 `merchantId` 注入，前端无需传。

**响应** `Boolean`

### 4.4 更新

`PUT /merchant/activity/cate/{merchantId}`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| cateCode | String | 是 | 分类唯一标识 |
| name | String | 是 | 分类名称 |
| torder | Integer | 否 | 排序 |

> 改名后会同步该分类下活动的 `cateName`。

**响应** `Boolean`

### 4.5 删除

`DELETE /merchant/activity/cate/{merchantId}/{cateCode}`

> 分类下仍有活动时不可删除。

**响应** `Boolean`

## 5. 优惠活动新增/更新选择分类

**路径**：`POST /merchant/activity/{merchantId}`、`PUT /merchant/activity/{merchantId}`

### 5.1 选择流程

1. 先调 `GET /merchant/activity/cate/{merchantId}/all`  
2. 选择后同时传：
   - `cateCode` = 分类 `uniqueCode`
   - `cateName` = 分类 `name`（冗余展示字段，建议一并传）

### 5.2 新增 Body 关键字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| cateCode | String | 否 | 活动分类标识 |
| cateName | String | 否 | 活动分类名称 |
| name | String | 是 | 活动名称 |
| startTime / endTime | LocalDateTime | 是 | 起止时间 |
| poster / detailPoster / content / ... | | 否 | 其余活动字段 |

**响应** `String`（活动 `uniqueCode`）

### 5.3 更新 Body 关键字段

在新增字段基础上增加：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| uniqueCode | String | 是 | 活动唯一标识 |
| cateCode / cateName | String | 否 | 可改分类 |

**响应** `Boolean`

### 5.4 列表/详情回显

`GET /merchant/activity/{merchantId}/page`  
`GET /merchant/activity/{merchantId}/detail?activityCode=`

返回字段含 `cateCode`、`cateName`，用于编辑页回选。

## 6. 服务人员（同步数字城市）

**后端**：`HousekeeperController` → `HousekeeperStaffManageService`  
**路径前缀**：`/housekeeper/staff`  
**说明**：站长维护管家服务下的服务人员；新增/更新会同步数字城市 APP 用户。

### 6.1 接口一览

| 说明 | 方法 | 路径 |
|------|------|------|
| 分页 | GET | `/housekeeper/staff/page` |
| 启用列表 | GET | `/housekeeper/staff/list?housekeeperId=` |
| 详情 | GET | `/housekeeper/staff/{staffId}` |
| 新增 | POST | `/housekeeper/staff` |
| 更新 | PUT | `/housekeeper/staff` |
| 启停 | PUT | `/housekeeper/staff/{staffId}/status?status=` |
| 删除 | DELETE | `/housekeeper/staff/{staffId}` |

### 6.2 分页 Query

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum / pageSize | Long | 是 | 分页 |
| housekeeperId | Long | 否 | 管家服务ID |
| staffName | String | 否 | 姓名模糊 |
| status | Integer | 否 | 1=启用，2=禁用 |

### 6.3 新增

`POST /housekeeper/staff`

```json
{
  "housekeeperId": 1,
  "staffName": "张师傅",
  "phone": "13800138000",
  "avatar": "https://...",
  "title": "保洁",
  "sortOrder": 1,
  "status": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| housekeeperId | Long | 是 | 所属管家服务 |
| staffName | String | 是 | 姓名 |
| phone | String | 是 | 手机号，须匹配 `^1[3-9]\d{9}$` |
| avatar | String | 否 | 头像 |
| title | String | 否 | 工种/职称 |
| sortOrder | Integer | 否 | 排序 |
| status | Integer | 否 | 1=启用，2=禁用 |

非法手机号返回参数错误：`手机号格式不正确`。

### 6.4 更新

`PUT /housekeeper/staff`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| staffId | Long | 是 | 服务人员ID |
| housekeeperId | Long | 是 | 管家服务ID |
| staffName | String | 是 | 姓名 |
| phone | String | 是 | 手机号（同新增校验） |
| avatar / title / sortOrder / status | | 否 | 同新增 |

### 6.5 响应 VO

`HousekeeperStaffVO`

| 字段 | 类型 | 说明 |
|------|------|------|
| staffId | Long | 人员ID |
| housekeeperId | Long | 管家服务ID |
| housekeeperName | String | 管家服务名称 |
| stationId | Long | 站长ID |
| staffName | String | 姓名 |
| phone | String | 手机号 |
| avatar | String | 头像 |
| title | String | 工种 |
| userId | Long | 本地登录用户ID（userType=8） |
| sortOrder / status | Integer | 排序/状态 |
| createTime / updateTime | LocalDateTime | 时间 |

### 6.6 同步数字城市说明（前端无需直接调用）

新增/更新服务人员时，后端自动执行：

1. **校验手机号**（大陆 11 位）  
2. **调用 city-api**：`POST /data/station/synAppUser`  
   - 入参：`phone`、`partnerId`（站长 `stationCode`）、`nickName`、`avatar`、`pwd`  
   - 出参：`userUniqueCode`（城市 APP `city_user_code`）  
3. **本地开通/更新账号**：`userType=8`（服务人员），写入 `cityUserCode`  
4. **落库服务人员**并绑定 `userId`

| 下游接口 | Method | 路径 | 说明 |
|----------|--------|------|------|
| 同步城市用户 | POST | city-api `/station/synAppUser` | 按手机号+合伙人查建用户，返回 `userUniqueCode` |

> 若数字城市同步暂失败，本地仍会开通服务人员账号（`cityUserCode` 可能为空），接口整体不因此失败；日志会有 warn。

#### city-api `synAppUser` 请求体（后端内部）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | String | 是 | 手机号 |
| partnerId | String | 是 | 站长 stationCode |
| nickName | String | 否 | 昵称，默认脱敏手机号 |
| avatar | String | 否 | 头像 |
| pwd | String | 否 | 明文密码 |

**响应 data**：`String`（`userUniqueCode` / `city_user_code`）

## 7. 前端对接建议

### 7.1 站长：商户分类 + 选分类

```
分类管理页：page / list / add / update / remove
商户表单：
  options = GET /station/merchant/category/list
  submit.categoryCode = selected.uniqueCode
  detail.categoryCode 回显选中项
```

### 7.2 商户：活动分类 + 选分类

```
分类管理页：/merchant/activity/cate/{merchantId}/...
活动表单：
  options = GET /merchant/activity/cate/{merchantId}/all
  submit.cateCode = selected.uniqueCode
  submit.cateName = selected.name
```

### 7.3 站长：服务人员

```
phone 前端可做同样正则预校验：/^1[3-9]\d{9}$/
提交后由后端同步数字城市，前端无需再调 synAppUser
```

### 7.4 易混路径对照

| 业务 | 正确路径 | 勿用 |
|------|----------|------|
| 商户分类（站长） | `/station/merchant/category/*` | `/merchant/cate/*`（那是商品分类） |
| 优惠活动分类 | `/merchant/activity/cate/*` | `/merchant/cate/*` |
| 商品分类 | `/merchant/cate/*` | — |
