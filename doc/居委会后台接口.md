# 居委会后台接口

基础地址：`http://主机:8202/web`

本文业务路径都写成 `/web/neighborhood/...`。例如村情指标列表是：

`GET http://主机:8202/web/neighborhood/stat/list`

## 请求约定

请求头：

```http
Authorization: Bearer <居委会token>
Content-Type: application/json
```

`Bearer` 和 token 之间有一个空格。必须是居委会账号，userType = 6。当前 token 不是居委会时返回：

```json
{ "code": 40032, "level": "api", "msg": "未查询到居委会信息", "data": null }
```

未登录：

```json
{ "code": 30002, "level": "user", "msg": "您还未登录或登录失效，请重新登录！", "data": null }
```

其他失败也是 `code` 非 0，`msg` 是提示文案，`data` 为 `null`。

成功包一层，下面每个接口只写 `data`：

```json
{ "code": 0, "level": null, "msg": "success", "data": true }
```

新增、更新、删除、审核、启停成功时 `data` 都是 `true`。列表的 `data` 是数组，没有数据是 `[]`。单条没有记录时返回对象，字段为 `null`。

`Long` 类型的 id 请求和返回都按字符串处理。时间 `yyyy-MM-dd HH:mm:ss`，日期 `yyyy-MM-dd`。金额是数字，单位元。图片先走现有上传接口，这里只传 URL。

更新是全量提交：把新增时的字段全部带上，再加主键。可选字段不传会存成空。

启用、禁用不走 body，走 query：`?status=1` 启用，`?status=2` 禁用。

这次不做：结对帮扶、居委会 AI 助手、居民 AI 助手、居民 AI 智能体。用药提醒没有后台接口，居民在客户端自己添加和打卡。

公告、活动中心、活动分类、广告、资讯、服务、热线、留言继续用原来的接口，路径前缀同样是 `/web/neighborhood`：

| 栏目 | 路径 |
| --- | --- |
| 公告 | `/web/neighborhood/notice` |
| 活动中心、活动报名 | `/web/neighborhood/activity` |
| 活动分类 | `/web/neighborhood/cate` |
| 广告 | `/web/neighborhood/banner` |
| 资讯 | `/web/neighborhood/dynamic` |
| 服务 | `/web/neighborhood/service` |
| 热线 | `/web/neighborhood/serviceGuide` |
| 留言 | `/web/neighborhood/leaveMessage` |

近期党建活动是新接口 `/web/neighborhood/party-activity`，不要和上面的 `activity` 混用。

## 登录

`POST /web/login/password`

这个接口不要带 token。

```json
{ "phone": "手机号", "password": "密码" }
```

```json
{
  "token": "访问令牌",
  "refreshToken": "刷新令牌",
  "expireTime": "2026-10-20 16:00:00",
  "user": {}
}
```

之后请求头用返回的 `token`。如果这个账号是站长而不是居委会，业务接口会返回 40032。这时用站长 token 再请求：

`GET /web/login/merchantToken/{merchantId}`

`merchantId` 是该村居委会的商户 ID。返回结构与登录相同，换成返回的 `token` 再调业务接口。

## 村情指标

`GET /web/neighborhood/stat/list`

```json
[
  {
    "statId": "1",
    "statCode": "household_count",
    "statName": "总户数",
    "statValue": "484",
    "unit": "户",
    "icon": null,
    "status": 1,
    "statusLabel": "启用",
    "sortOrder": 1
  }
]
```

`POST /web/neighborhood/stat`

```json
{
  "statName": "总户数",
  "statValue": "484",
  "unit": "户",
  "icon": null,
  "status": 1,
  "sortOrder": 1
}
```

`statName` 必填。`status` 不传默认 1。`sortOrder` 不传默认 0，小的在前。不要传 `statCode`，服务端生成。

`PUT /web/neighborhood/stat`

在新增字段上加 `statId`。`statCode` 不能改。

`PUT /web/neighborhood/stat/{statId}/status?status=1`

`DELETE /web/neighborhood/stat/{statId}`

已有编码不要改名换义，居民端按 `statCode` 取数：

| statCode | 页面 |
| --- | --- |
| household_count | 首页总户数 |
| population | 首页常住人口 |
| party_member | 首页党员人数 |
| leadership | 首页班子成员 |
| garbage_rate | 环境页垃圾分类覆盖率 |
| beautiful_yard | 环境页美丽庭院 |
| illegal_build | 环境页本月违建 |

改这三个环境数字，就是更新对应指标的 `statValue`。环境页没有单独的保存接口。

## 志愿服务

志愿者列表和报名审核是同一张表，用状态分开。

| status | 含义 | 出现在 |
| --- | --- | --- |
| 1 | 待审核 | 报名列表 |
| 2 | 正常 | 志愿者列表，居民端计入人数和时长 |
| 3 | 已拒绝 | 报名列表 |
| 4 | 停用 | 志愿者列表 |

后台直接建志愿者，只能是正常或停用。

```json
{
  "userId": "10001",
  "userName": "王建国",
  "userPhone": "13800000000",
  "intro": "家电维修",
  "businessHours": "周末",
  "status": 2
}
```

`userName` 必填。`userId` 可空。`status` 只能是 2 或 4，不传默认 2。

`PUT /web/neighborhood/volunteer` 加 `volunteerId`。`status` 同样只能是 2 或 4。

`DELETE /web/neighborhood/volunteer/{volunteerId}`

会同时删掉这个人的时长记录。

`PUT /web/neighborhood/volunteer-apply`

```json
{ "volunteerId": "1", "status": 2 }
```

`status` 只能是 2 通过或 3 拒绝。只能审 `status = 1` 的记录。通过后从报名列表消失，出现在志愿者列表。

`POST /web/neighborhood/volunteer-log`

```json
{
  "volunteerId": "1",
  "name": "月末清洁日",
  "signDate": "2026-06-28",
  "hours": 4
}
```

四个都要传。只能给 `status = 2` 的志愿者加。加完 `hours` 自动增加。
