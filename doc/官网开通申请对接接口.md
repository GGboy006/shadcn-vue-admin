# 官网开通申请对接接口

> **模块**：`residential-web`  
> **页面**：小区站长官网 `/marketing`「联系实施同学开通」表单  
> **适用端**：未登录访客（提交申请）；实施/运营后台（跟进列表，建议同期做）  
> **建议控制器**：`OpenStationApplyController`  
> **接口前缀**：`/open/station-apply`  
> **Context-Path**：`/web`（完整前缀示例：`/residential-web/web`）  
> **Content-Type**：`application/json`  
> **统一响应**：`BaseResponse<T>` → `{ code, level, msg, data }`，成功时 `code = 0`  
> **时间格式**：`yyyy-MM-dd HH:mm:ss`  
> **文档用途**：给后端 AI 实现接口；前端字段名已与现网表单对齐，不要改名。

---

## 0. 业务说明

官网不是自助注册。访客填写小区和联系方式，由实施同学人工开通「一个小区一个站长驾驶舱」。

| 概念 | 说明 |
|------|------|
| 申请 | 一条开通意向，未登录即可提交 |
| 身份 | 填表人角色，**不是**开通后的 `userType`。开通后站长仍是 `userType=3` |
| 跟进 | 实施同学联系手机号，再走现有站长开通流程创建账号。本接口不负责开户 |

前端当前提交只写入浏览器 localStorage。本接口上线后改为 `POST /open/station-apply`。

```text
访客填表 → POST /open/station-apply
实施同学 → POST /open/station-apply/page 看待处理
联系客户后 → PUT /open/station-apply/status
真正开户仍走现有站长开通能力
```

---

## 1. 接口一览

| 优先级 | 说明 | 方法 | 路径 | 鉴权 |
|--------|------|------|------|------|
| P0 必做 | 提交开通申请 | POST | `/open/station-apply` | **无 token**，网关必须放行 |
| P1 建议 | 申请分页（实施/运营） | POST | `/open/station-apply/page` | 需登录；建议 userType=3 或内部运营 |
| P1 建议 | 更新跟进状态 | PUT | `/open/station-apply/status` | 同上 |


---

## 2. P0 · 提交开通申请

```
POST /open/station-apply
```

**鉴权**：无。访客从官网提交，没有 token。若网关默认校验 Authorization，必须把该路径加入白名单。

### 2.1 请求体 `StationApplyAddDTO`

字段名必须与下表一致（前端表单原样提交，不要改名）。

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| communityName | string | 是 | trim 后 1~40 字 | 小区名称 |
| contactName | string | 是 | trim 后 1~20 字 | 联系人 |
| phone | string | 是 | 正则 `^1[3-9]\d{9}$` | 11 位大陆手机号 |
| identity | string | 是 | 仅 `property` / `committee` / `other` | 填表人身份 |
| remark | string | 否 | trim 后最多 200 字；空串当未填 | 备注 |

**identity 枚举（字符串，禁止改成数字 3/4/5/6）**

| 值 | 含义 |
|----|------|
| property | 物业 / 社区运营商 |
| committee | 街道 / 居委会 |
| other | 其他 |

这不是登录态 userType。开通后站长账号仍是 userType=3。

**请求示例**

```json
{
  "communityName": "桂园小区",
  "contactName": "张三",
  "phone": "13800138000",
  "identity": "property",
  "remark": "预计 20 家商户，希望下月上线"
}
```

未填备注可不传 remark，或传空串 / null。

### 2.2 响应 `StationApplySubmitVO`

```json
{
  "code": 0,
  "level": null,
  "msg": "success",
  "data": {
    "applyId": "1850000000000000001"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| applyId | string | 申请单 ID。雪花 Long 必须按字符串返回，避免 JS 精度丢失 |

前端成功只看 code===0。applyId 可返回，前端这一期可以不展示。

### 2.3 错误

参数错误用现有参数错误码（如 40001），msg 用中文，前端会 toast msg。

| 场景 | msg |
|------|------|
| 小区名称为空 | 请填写小区名称 |
| 联系人为空 | 请填写联系人 |
| 手机号非法 | 请输入正确的 11 位手机号 |
| identity 非枚举 | 请选择您的身份 |
| 备注超 200 字 | 备注不超过 200 字 |

防刷建议（前端不做）：

| 规则 | 失败 msg |
|------|----------|
| 同一手机号 24 小时内重复提交 | 该手机号已提交过申请，请等待实施同学联系 |
| 同一 IP 短时高频 | 提交过于频繁，请稍后再试 |

重复提交建议单独业务码（如 40010），不要当系统错误。


### 2.4 落库建议

新建表 `station_open_apply`：

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint | 主键，雪花 |
| community_name | varchar(40) | 小区名称 |
| contact_name | varchar(20) | 联系人 |
| phone | varchar(11) | 手机号 |
| identity | varchar(20) | property / committee / other |
| remark | varchar(200) | 可空 |
| status | tinyint | 0待处理 1已联系 2已开通 3已关闭，默认 0 |
| client_ip | varchar(64) | 可选 |
| user_agent | varchar(255) | 可选 |
| create_time | datetime | 提交时间 |
| update_time | datetime | 状态变更时间 |
| follow_remark | varchar(200) | 实施内部备注，不要回给出提交接口 |

本接口只收线索，禁止在此创建站长账号、小区、token。

## 3. P1 · 申请分页（实施/运营）

没有列表则申请进黑洞，建议与 P0 同期做。

```
POST /open/station-apply/page
```

鉴权：需要 token。建议仅内部运营或站长 userType=3。

### 3.1 请求体 `StationApplyPageDTO`

对齐现有 PageParam：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | int | 是 | 从 1 开始 |
| pageSize | int | 是 | 最大 200 |
| searchCount | boolean | 否 | 是否查总条数，默认 true |
| phone | string | 否 | 手机号筛选 |
| communityName | string | 否 | 小区名称模糊 |
| identity | string | 否 | 枚举筛选 |
| status | int | 否 | 跟进状态 |

### 3.2 响应 `PageResult<StationApplyVO>`

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "pageNum": 1,
    "pageSize": 10,
    "total": 1,
    "pages": 1,
    "emptyFlag": false,
    "list": [
      {
        "applyId": "1850000000000000001",
        "communityName": "桂园小区",
        "contactName": "张三",
        "phone": "13800138000",
        "identity": "property",
        "identityName": "物业 / 社区运营商",
        "remark": "预计 20 家商户",
        "status": 0,
        "statusName": "待处理",
        "createTime": "2026-08-27 16:20:00"
      }
    ]
  }
}
```

applyId 按字符串返回。identityName / statusName 由后端带上。

## 4. P1 · 更新跟进状态

```
PUT /open/station-apply/status
```

鉴权同分页。请求体 `StationApplyStatusDTO`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| applyId | string | 是 | 申请单 ID |
| status | int | 是 | 1已联系 2已开通 3已关闭 |
| followRemark | string | 否 | 内部备注，最多 200 字 |

不允许访客调用。成功时 data 可为 null 或最新 StationApplyVO。

---

## 5. 枚举

identity：property=物业/社区运营商，committee=街道/居委会，other=其他。

status：0待处理，1已联系，2已开通，3已关闭。

---

## 6. 给后端 AI 的实现约束

1. 提交接口必须匿名可访问，不要套用必须登录的 /station/* 鉴权。
2. 字段 camelCase，与前端一致。
3. ID 一律 string 出参。
4. 只记线索，不创建站长/商户/居委会账号。
5. identity 用字符串枚举，不要改成 userType 数字。
6. 统一 BaseResponse，code=0 成功；校验失败用中文 msg。
7. 建议 phone 24 小时去重。
8. 企微/飞书/短信通知可选，且不阻塞提交成功。
9. 日志里手机号可打掩码。
10. 不要改现有 /login/*。

---

## 7. 前端对接约定

```ts
await apiFetch("/open/station-apply", {
  method: "POST",
  body: {
    communityName,
    contactName,
    phone,
    identity, // property | committee | other
    remark: remark || undefined,
  },
})
```

未登录时 useApiFetch 不会带 Authorization。成功看 code===0。失败由拦截器 toast msg。

完整 URL 示例：`{VITE_SERVER_API_URL}/residential-web/web/open/station-apply`
