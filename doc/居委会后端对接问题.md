# 居委会后端对接问题

测试范围：村务治理、居民服务。下面是需要后端配合的问题。前端能单独改完的不写在这里。

## 1. 发展党员公示状态改为按起止时间自动计算

现在 `status` 由后台手选：`1` 公示中，`2` 已结束，默认公示中。`startTime`、`endTime` 只是随记录保存，到点不会改状态。`remainDays` 已由接口计算。

这样会和日期打架。开始时间还没到，只要选了公示中，列表和党建概览的「公示中」条数都会把它算进去。结束时间过了，不手改就一直是公示中。

请改为由开始、结束时间算出展示状态，前端不再手选：

| 条件 | 展示 |
| --- | --- |
| 当前时间早于开始时间 | 未开始 |
| 在开始、结束时间之间 | 公示中 |
| 当前时间晚于结束时间 | 已结束 |

这是算出来的结果，不是再加一个手选枚举。概览里的 `publishingCount` 只统计落在公示期内的记录。

请确认一件事：公示期内能不能提前结束。

- 要提前结束：单独提供一个动作，前端只在那时改状态。
- 不要提前结束：状态完全跟时间走，新增和更新都不再接收手选 `status`。

前端约定：公示开始、结束时间按所选日期的 `00:00:00` 提交，格式 `yyyy-MM-dd HH:mm:ss`，不使用填写当时的时分秒。
