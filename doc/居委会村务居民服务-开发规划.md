# 居委会村务 / 居民服务开发规划

> 依据：后端《居委会后台接口》（2026-10-15）。接口比产品原型新，字段和按钮以接口为准。
> 原型只说明有哪些业务块，不照着做交互。
> 状态：第一批已接接口（村情数据、财务公开、党建管理），菜单仍只在开发环境显示。第二批及以后未做。

公告、活动、广告、资讯、栏目、专题、居委会信息、热线、留言继续用原来的接口，不在本文范围。

## 原则

- 页面沿用现有居委会写法：`BasicPage`、表格、抽屉表单、`vee-validate` + `zod`。
- 新接口列表是整包数组，表格用前端分页，不传 `pageNum`。
- 主键按字符串处理。更新时带上新增的全部字段，再加主键。可选字段不传会存成空。
- 不传 `partnerId`、`regionCode`、`stationId`、`stationCode`、`stationRegionCode`。登录必须是居委会 token（userType = 6）。
- 图片先走现有上传，接口只传 URL。HTML 正文用现有富文本，普通说明用 `Textarea`。
- 只读字段只展示：村情 `statCode`、财务 `balance`、党费 `feeRate`、志愿者累计 `hours`、议事选项上的票数。

## 四种页面

| 类型 | 形态 | 代表 |
| --- | --- | --- |
| 列表台账 | 表格 + 新增/编辑抽屉 + 删除。有 `PUT /{id}/status` 的，行内开关单独打这个接口；状态只在 body 里的，放表单下拉 | 村情指标、班子、财务、党建四个列表、积分规则和商品、调解员、消防文章和电话、环境动态和对比 |
| 工单 | 列表按状态给行操作。列表字段不全时，详情再请求单条 | 报修、议事、信箱、志愿报名、调解申请 |
| 一个村一条 | 打开即回填，底部保存。没有表格 | 村务公开、党务公开、履职承诺、助餐政策、津贴流程、挂号配置、消防联防 |
| 只读 | 统计卡片，无保存 | 党建概览 |

同一条正文只留一个编辑入口。公开正文 type 4 放养老页（`PUT /neighborhood/elder-flow`），type 5 放消防页（`PUT /neighborhood/fire-note`）。村务公开、党务公开、履职承诺用 `PUT /neighborhood/open`。

## 这次不做

结对帮扶、居委会 AI、居民 AI、用药提醒。班子只有一套名单，状态是启用或禁用，没有在职、离任、复职。议事不录入票数。书记信箱后台不能新建。

## 第一批

### 村情数据 `/neighborhood/village-data`

- [x] 指标：`GET/POST/PUT /neighborhood/stat`，`PUT /neighborhood/stat/{statId}/status?status=1|2`，`DELETE /neighborhood/stat/{statId}`。名称必填。不提交 `statCode`。
- [x] 班子：`/neighborhood/member`，启停路径同上。姓名、职务必填。居民端只显示启用。
- [x] 村务公开：公开正文 type = 1，一个村一条富文本。

### 财务公开 `/neighborhood/finance`

- [x] `/neighborhood/finance` 列表和增删改。月份 `yyyy-MM`、收入、支出必填。结余只读。状态 1 公示中，2 已归档，放表单里。没有单独的归档接口。

### 党建管理 `/neighborhood/party-building`

- [x] 概览：`GET /neighborhood/party/summary`，只读。
- [x] 发展党员公示：`/neighborhood/publicity`。姓名必填。性别 1 男 2 女。类型 1 入党积极分子，2 发展对象，3 预备党员转正。状态 1 公示中，2 已结束。
- [x] 三会一课：`/neighborhood/meeting`。类型、名称必填。类型 1 支部党员大会，2 支部委员会，3 党小组会，4 党课。状态 1 计划中，2 已召开。
- [x] 党费：`/neighborhood/fee`。名称、应缴人数、实缴人数、总额必填。比例只读。状态 1 收缴中，2 已完成。
- [x] 近期活动：`/neighborhood/party-activity`。不要和原来的活动中心混用。名称必填。状态 1 计划中，2 进行中，3 已完成。
- [x] 党务公开：公开正文 type = 2。履职承诺：type = 3。

## 第二批

### 报事报修 `/neighborhood/repairs`

- [ ] 列表 `GET /neighborhood/repair/list`，详情 `GET /neighborhood/repair/{repairId}`（进度只在详情里）。
- [ ] 新增、编辑、删除。类型、问题描述必填。类型 1 道路破损，2 路灯故障，3 垃圾堆积，4 水管问题，5 公共设施，6 其他。工单号只展示。
- [ ] 记进度：`POST /neighborhood/repair/progress`。进度状态 1 关键节点，2 普通进度。`finish=1` 同时办结，`finish=2` 不改工单状态。工单状态 1 待处理，2 处理中，3 已办结。

### 村民议事 `/neighborhood/affairs`

- [ ] 列表和详情。新增、编辑、删除走 `/neighborhood/affair`。名称、类型必填。
- [ ] 状态直接改在编辑里：1 待审核，2 讨论中，3 方案中，4 投票中，5 已解决，6 已驳回。审核意见用 `replyContent`。
- [ ] 状态为投票中时，`options` 必填，2 到 6 个字符串。改选项会整组重写。票数只在详情展示。
- [ ] 类型 1 基础设施，2 环境卫生，3 公共服务，4 文体活动，5 其他。

### 书记信箱 `/neighborhood/mailbox`

- [ ] 列表和详情。无新增。
- [ ] 回复：`PUT /neighborhood/mail/reply`。`mailId`、回复内容必填。可改是否公开（1 公开，2 不公开）和状态（2 已回复，3 已办结，默认 2）。
- [ ] 办结：`PUT /neighborhood/mail/{mailId}/finish`，无 body。
- [ ] 删除。

### 志愿服务 `/neighborhood/volunteers`

同一张表，两个列表：

- [ ] 志愿者列表 `GET /neighborhood/volunteer/list`：状态 2 正常，4 停用。后台直接新建只能是这两种。姓名必填。累计时长不在新增里填。
- [ ] 报名列表 `GET /neighborhood/volunteer-apply/list`：状态 1 待审核，3 已拒绝。审核 `PUT /neighborhood/volunteer-apply`，只能把待审核改成 2 通过或 3 拒绝。
- [ ] 详情才有时长明细。记时长 `POST /neighborhood/volunteer-log`，四个字段都要传，只能给状态为正常的人记。
- [ ] 编辑、删除。删除会同时删掉这个人的时长记录。

### 矛盾调解 `/neighborhood/mediation`

- [ ] 调解员：`/neighborhood/mediator` 列表台账。姓名必填。状态 1 在岗，2 停用。
- [ ] 申请：列表、详情、新增、编辑、删除。申请人、类型、事情经过必填。类型 1 邻里，2 土地，3 家庭，4 债务，5 其他。状态 1 待受理，2 调解中，3 已达成，4 已结案。
- [ ] 受理：`PUT /neighborhood/mediate/accept`，带申请 ID 和调解员 ID。

## 第三批

### 积分管理 `/neighborhood/points`

四个页签，各自一张表。

- [ ] 规则：`/neighborhood/point-rule`。名称、类型、分值必填。分值可以是负数。类型 1 志愿服务，2 文明行为，3 学习提升，4 违规扣分。状态 1 启用，2 禁用。
- [ ] 账户：只有列表和加减分。`POST /neighborhood/point-account/adjust` 用该行的 `userId`。正数加，负数减，减完不能小于 0。没有新增居民。
- [ ] 商品：`/neighborhood/point-goods`。名称、所需积分必填。状态 1 上架，2 下架。
- [ ] 兑换：列表、代兑 `POST /neighborhood/point-exchange`（`userId` + `goodsId`）、领取 `PUT /neighborhood/point-exchange/{exchangeId}/receive`。成功后重新拉账户、商品和兑换记录。

### 养老服务 `/neighborhood/elderly`

- [ ] 助餐政策：`GET/PUT /neighborhood/elder-meal`，一个村一条。
- [ ] 助餐老人：`/neighborhood/elder-person`。姓名必填。状态 1 正常，2 停用。
- [ ] 津贴标准：`/neighborhood/elder-allowance`。名称、每月补贴必填。
- [ ] 申请流程：`GET/PUT /neighborhood/elder-flow`，富文本，即公开正文 type = 4。
- [ ] 探访志愿者：`/neighborhood/elder-visitor`。独立名单，不关联志愿服务里的人。姓名必填。
- [ ] 探访对象：`/neighborhood/elder-visit`。姓名、频率必填。频率 1 每周一次，2 每周两次，3 每两周一次，4 每月一次。状态 1 正常，2 重点关注。

### 医疗健康 `/neighborhood/healthcare`

用药提醒没有后台接口。

- [ ] 档案：`/neighborhood/health`。姓名必填。性别 1 男 2 女。状态 1 已建档，2 未建档。身高厘米，体重千克。不填 `userId` 时居民端看不到。
- [ ] 签约：`/neighborhood/health-sign`。姓名必填。状态 1 已签约，2 已到期，3 已解约。续签、解约用编辑改有效期和状态，没有单独接口。同样依赖 `userId`。
- [ ] 挂号：`GET/PUT /neighborhood/health-book`，一个村一条。类型必填。1 外部 H5，填 `externalUrl`。2 微信小程序，`name` 是小程序名，`remark` 是路径。状态 1 启用，2 禁用。
