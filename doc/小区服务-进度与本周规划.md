### 3.2 建议开发顺序

**第一梯队(标准页面,快速推进)**

1. **居民管理**(最简单,只读列表+详情,跑通 B 类 Long ID 套路)
2. **知识服务**(3 个标准 CRUD 子页面:分类/文章/问答,复用 A 类模式;但需先确认菜单是否拆 3 子页)

**第二梯队(需先定方案)**

3. **意见反馈**(统计卡片 + 列表 + 状态变更/回复弹窗)
4. **社区电话**(父级-子级树形/分组展示)
5. **管家服务**(4 子模块:主体/人员/分类/分配;分配是全量覆盖式交互)
6. **居民AI工具**(选分类 → 选候选 Agent → 开通的流程化交互,无传统编辑)

### 3.3 待确认事项(开发前需拍板)

2. **知识服务菜单结构**:是单页带 tab(分类/文章/问答),还是拆 3 个子菜单?
