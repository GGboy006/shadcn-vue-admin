### 3.2 已完成模块要点

- **居民管理**:只读列表 + 详情 Modal,行操作仅「查看」。居民 VO 含 `aiToolCount`(使用次数,统计字段)。
- **知识服务**:Tabs 容器(知识分类 / 快捷问答);分类下钻页 `[categoryId].vue` 锁定分类看文章;全局文章页 `articles.vue`;快捷问答标准 CRUD。
- **社区电话**:父级分类 + 子级电话列表,联系电话列支持一键复制。
- **意见反馈**:4 张统计卡片(全部/待处理/已处理/已回复)可点击筛选;行操作按状态显隐(查看/回复/标记已处理/删除);不做新增接口(居民端提交)。
- **管家服务**:单菜单 + Tabs(服务分类 / 服务主体 / 服务人员);分类行操作「分配人员」钻取到 `[categoryId].vue`,本地编辑 + 统一保存(全量覆盖 PUT),diff 提示 + 清空二次确认 + 未保存离开拦截。

### 3.3 阻塞:居民AI工具(后端口径冲突)

> 详见 `src/pages/community/resident/RESIDENT-AI-TOOL-CONFLICT.md`

第 6 节接口(`assign` 无 `residentId`、候选池按站长维度、文档明说不写居民分配关系表)无法承载「给单个居民开通」的语义,与原计划(居民列表行操作跳转分配页)不闭环。

三选一待后端确认:
1. 口径是「全小区共享」→ 做全局管理页(用第 6 节接口,不带 residentId)
2. 后端改接口加 `residentId` → 补 API 封装 + 居民分配页
3. token/header 隐式传居民标识 → 技术上不通,已排除

**当前处置**:侧边栏「居民AI工具」菜单已下线(`7ed80c2`),避免指向无效占位页;API 层(`resident-ai-tool.api.ts`)已就绪,方案 1 确认后可直接用。
