# 项目二次开发顺序

> 基于 shadcn-vue-admin 后台管理系统的开发路线图

## 总体原则

按 **"地基 → 权限 → 系统 → 业务"** 四层推进，逐层夯实再往下走。

---

## 第一阶段：地基（预计 1-2 天）

**目标**：让系统能跑起来，有真实用户可以登录使用。

| 序号 | 模块                                    | 说明                                             |
| ---- | --------------------------------------- | ------------------------------------------------ |
| 1    | 登录 / 注册(暂时不做注册，按钮我已隐藏) | 对接后端登录接口，替换现有 Mock                  |
| 2    | 路由守卫                                | 未登录用户拦截到登录页，已登录用户禁止访问登录页 |
| 3    | 请求拦截器                              | 自动注入 Token，401 时清除状态并跳转             |
| 4    | 全局错误处理                            | 接口异常统一用 toast / dialog 提示，不抛到控制台 |
| 5    | 退出登录                                | 清除 Pinia 状态、本地缓存，跳转登录页            |

**验收标准**：

- [ ] 能用真实账号密码登录并进入首页
- [ ] 清掉 Cookie/Storage 后刷新，自动回到登录页
- [ ] 接口 401 时自动退出，无白屏

---

## 第二阶段：权限骨架（预计 2-3 天）

**目标**：不同角色看到不同的菜单、页面和按钮。

| 序号 | 模块             | 说明                                              |
| ---- | ---------------- | ------------------------------------------------- |
| 1    | 角色管理         | 角色的增删改查（如：超级管理员、运营、普通用户）  |
| 2    | 菜单权限         | 控制左侧导航栏的显示 / 隐藏                       |
| 3    | 按钮权限         | 页面内"新增 / 编辑 / 删除 / 导出"等按钮的显隐控制 |
| 4    | 用户-角色绑定    | 一个用户可拥有多个角色                            |
| 5    | 接口权限（可选） | 前端只做按钮级，接口级校验由后端负责              |

**验收标准**：

- [ ] 普通用户登录后看不到"用户管理"菜单
- [ ] 无删除权限的用户看不到删除按钮
- [ ] 直接 URL 访问无权限页面时，提示 403 或跳转 403 页

---

## 第三阶段：系统管理（预计 2-3 天）

**目标**：平台级功能，运营人员日常维护所需。

| 序号 | 模块             | 说明                               |
| ---- | ---------------- | ---------------------------------- |
| 1    | 用户管理         | 调整现有页面字段，对接真实用户表   |
| 2    | 操作日志         | 记录谁、在什么时间、做了什么操作   |
| 3    | 系统配置         | 网站名称、Logo、版权信息、开关项等 |
| 4    | 字典管理（可选） | 性别、状态、类型等下拉选项统一管理 |

**验收标准**：

- [ ] 能在后台新增用户并分配角色
- [ ] 关键操作（删除、修改权限）有日志记录
- [ ] 配置项修改后即时生效

---

## 第四阶段：具体业务（长期迭代）

**目标**：你的核心业务功能，按需拆分模块。

### 4.1 单个业务模块的标准开发顺序

每个新模块建议按以下顺序开发：

```
列表页（Table）
  ├── 搜索条件
  ├── 数据表格（分页、排序、列显隐）
  └── 批量操作

表单页（Form）
  ├── 新增弹窗 / 页面
  ├── 编辑弹窗 / 页面
  └── 表单校验（VeeValidate + Zod）

详情页（Detail）
  ├── 只读详情展示
  └── 关联信息（Tab / Card）

扩展功能
  ├── 导入（Excel）
  ├── 导出（Excel / PDF）
  └── 数据权限（只看自己的 / 看部门的 / 看全部的）
```

### 4.2 示例模块拆分

| 模块     | 典型页面                       | 备注   |
| -------- | ------------------------------ | ------ |
| 订单管理 | 订单列表、订单详情、发货处理   | 电商类 |
| 内容管理 | 文章列表、分类管理、富文本编辑 | CMS 类 |
| 商品管理 | SPU / SKU、库存、上下架        | 电商类 |
| 财务管理 | 账单流水、对账、提现审核       | 平台类 |

---

## 为什么是这个顺序？

| 阶段     | 如果不先做，后面会怎样                       |
| -------- | -------------------------------------------- |
| 地基     | 每做一个页面都要处理登录态，重复劳动         |
| 权限     | 做完业务再补权限，每个页面都要回头改按钮显隐 |
| 系统管理 | 运营人员无法自助维护，所有改动都要开发介入   |
| 业务     | 依赖前三阶段的能力，顺序错了返工量大         |

---

## 开发节奏建议

- **小步快跑**：每个阶段完成后跑通全流程，不要堆积到最后一刻联调。
- **Mock 先行**：后端接口未就绪时，先用本地 Mock 数据把页面搭起来。
- **复用现有组件**：优先使用项目已有的 `DataTable`、`BasicPage`、`UserForm` 等模式，保持风格一致。
